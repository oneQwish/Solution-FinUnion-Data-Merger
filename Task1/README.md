# Задание 1. Анализ данных, сущностей и хранилищ

Допущение: сделка — покупка с последующим присоединением RetailBank к FinUnion. До завершения реорганизации RetailBank остаётся отдельным юрлицом; после неё FinUnion — правопреемник, договоры RetailBank переходят без перезаключения. Целевыми считаются системы FinUnion.

| logical-data-model.md | ERD в Mermaid и решения по связям; PNG — diagrams/logical-data-model.png |

| reference-model.md | Маппинг 10 сущностей на области BIAN и роль BIAN в объединении |

Ключевые решения:

- Клиент связан с договором через сущность «Участник договора» с ролью, счёт — через договор: при склейке дублей в MDM клиент упоминается в одном месте.
- MDM ведёт клиентов и справочники; счета, операции, карты и кредиты остаются в профильных банковских системах.
- Регламентированная отчётность — в DWH; большие исторические и событийные данные — в Lakehouse на основе Data Lake FinUnion; документы и архив RetailBank — в объектном хранилище.
- С BIAN сопоставлены сущности, по которым в кейсе названы расхождения между банками.
