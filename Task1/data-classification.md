# Классификация данных

Влияние оценено по регуляторным, финансовым, операционным и репутационным последствиям утечки или искажения.

| Сущность | Категория данных | Критичность | Влияние на ИБ | Средства защиты |
|---|---|---|---|---|
| Клиент — физлицо (включая ИП) | ПДн, в том числе паспорт, ИНН, СНИЛС; банковская тайна | Высокая | Утечка нарушает 152-ФЗ и ст. 26 закона о банках: штрафы, социальная инженерия против клиентов, репутационный ущерб | Шифрование при хранении и передаче, маскирование вне продуктивного контура, RBAC, аудит доступа |
| Клиент — юрлицо | Банковская тайна; ПДн представителей и контактных лиц | Высокая | Раскрытие сведений о клиенте нарушает ст. 26 закона о банках | Шифрование при хранении и передаче, RBAC, аудит доступа |
| Договор | ПДн, банковская тайна | Высокая | Раскрытие условий обслуживания клиента нарушает 152-ФЗ и ст. 26 закона о банках | Шифрование, RBAC, аудит доступа, контроль целостности сканов |
| Счёт | Банковская тайна | Высокая | Раскрытие остатков и реквизитов, риск мошенничества | Шифрование, RBAC, аудит доступа, маскирование номера в аналитике |
| Карта | Данные платёжных карт, ПДн | Высокая | Компрометация карт, нарушение PCI DSS; перевыпуск карт и компенсации клиентам | Токенизация номера, хранение полного номера только в процессинге, шифрование, сегментация сети |
| Кредит | Банковская тайна, ПДн, данные кредитной истории | Высокая | Раскрытие долговой нагрузки клиента, нарушение 218-ФЗ | Шифрование, RBAC, аудит доступа, маскирование в аналитике |
| Транзакция | Банковская тайна, финансовые данные | Высокая | Раскрытие операций клиента; искажение ведёт к ошибкам в учёте и отчётности | Шифрование, RBAC, неизменяемый журнал, контроль целостности, сверка с Core |
| Платёж | Банковская тайна, финансовые данные | Высокая | Подмена реквизитов, мошеннические переводы; искажение останавливает исполнение платежей | Шифрование, RBAC, контроль целостности, антифрод-проверка, аудит |
| Обращение | ПДн, может содержать банковскую тайну | Высокая | Раскрытие жалоб и персональных обстоятельств клиента; ПДн в свободном тексте труднее всего маскировать | RBAC, маскирование ПДн в свободном тексте, аудит доступа |
| Согласие на обработку ПДн | ПДн, юридически значимые данные | Высокая | Обработка без действующего согласия нарушает 152-ФЗ | Контроль целостности, неизменяемая история, аудит изменений, RBAC |
| Продукт | Публичные и внутренние данные | Низкая | Ошибка ведёт к неверным продажам и отчётности, утечка некритична | Контроль изменений, RBAC на редактирование |
| Тариф | Публичные данные | Средняя | Ошибка ведёт к неверным списаниям с клиентов | Контроль изменений, версионирование, RBAC на редактирование |
| Отделение | Публичные данные | Низкая | Ошибка искажает отчётность по регионам | Контроль изменений, RBAC на редактирование |
| Сегмент клиента | Внутренние данные, коммерческая тайна | Средняя | Раскрытие модели сегментации конкурентам | RBAC, контроль изменений |

## Персональные данные в аналитическом контуре

- Сырые данные с ПДн лежат только в изолированных сырых слоях — staging DWH и Bronze Lakehouse; доступ к ним есть только у инженеров данных. При переходе в core DWH и Silver Lakehouse ПДн заменяются глобальным ID из MDM: ФИО, документы и контакты в core, витрины, Silver и Gold не попадают.
- Соответствие глобального ID и персональных данных хранится только в MDM: доступ по ролям, каждое обращение журналируется.
- Квази-идентификаторы огрубляются: дата рождения — до года, адрес — до региона.
- По 152-ФЗ это обезличивание: данные остаются персональными, поэтому требования к защите DWH и Lakehouse не снижаются. Риск реидентификации перед публикацией витрины подтверждают Data Office и ИБ.
- Тот же режим действует для всех копий: реплик, резервных копий, журналов CDC, топиков Kafka с ПДн и копий для тестовых прогонов миграции.

Средства защиты сверяются с моделью угроз банка, которую ведёт подразделение ИБ; классификация согласуется с ним до утверждения схем данных.
