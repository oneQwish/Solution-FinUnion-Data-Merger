# Референсная модель BIAN

С BIAN сопоставлены сущности, по которым в кейсе названы расхождения между FinUnion и RetailBank: разные идентификаторы клиентов, разные модели счетов, договоров и операций, разные статусы карт и тарифы, разные правила кредитных продуктов, несинхронизированные справочники продуктов, тарифов и отделений. Дополнительно включён платёж: граница владения платёжными данными нужна для назначения мастер-систем. Сегмент клиента не включён: в BIAN нет области для справочника сегментов. Обращение и согласие не включены: расхождения по ним в кейсе не названы.

## Маппинг сущностей

| Сущность | Область BIAN | Зачем это нужно |
|---|---|---|
| Клиент | Party Data Management | Основа золотой записи в MDM: одни идентифицирующие атрибуты и правила сопоставления для клиентов обоих банков |
| Договор | Customer Agreement | Договоры FU и RB сводятся к одной типологии: ДБО, заявления к нему, договоры счёта, вклада, кредита, карты |
| Счёт | Current Account | Одна модель счёта вместо моделей FU и RB |
| Транзакция | Current Account (операции по счёту), Card Transaction Switch (карточные операции) | Типы операций обоих банков сводятся к одному справочнику для сверки и отчётности |
| Карта | Issued Device Administration | Статусы карт RB сопоставляются со статусами FU |
| Кредит | Consumer Loan (розница), Corporate Loan (МСБ) | Правила продуктов, стадии просрочки и расчёт задолженности RB приводятся к правилам FU |
| Продукт | Product Directory | Каталог продуктов, где каждому продукту RB сопоставлен продукт FU |
| Отделение | Branch Location Management | Справочник отделений обоих банков для отчётности по регионам |
| Тариф | Product Directory, Special Pricing Conditions (частичное соответствие) | Стандартные условия в BIAN — часть описания продукта; Special Pricing Conditions покрывает только особые условия, которые перекрывают стандартные. Отдельной области для тарифной сетки нет, поэтому тарифы ведутся вместе с каталогом продуктов |
| Платёж | Payment Order | Статусы платёжных распоряжений обоих банков сводятся к одному набору |

## Как BIAN помогает

### Унифицировать терминологию после слияния

Спорные понятия сводятся к определениям BIAN, а не к варианту одного из банков. Это касается типов договоров, статусов карт, видов счетов и операций, которые у FU и RB устроены по-разному.

### Определить границы владения данными

Каждая область BIAN — отдельная зона ответственности со своей мастер-системой. Владелец назначается по бизнес-направлению: где область обслуживает и физлиц, и юрлиц, данные делятся между Розничным бизнесом и МСБ по типу клиента. Это основа для назначения мастер-систем и владельцев в задании 2.

| Область BIAN | Зона владения |
|---|---|
| Party Data Management | Клиентские данные, MDM |
| Customer Agreement | Договоры |
| Current Account | Счета и операции по ним, Core |
| Issued Device Administration, Card Transaction Switch | Карты и карточные операции, карточный процессинг |
| Consumer Loan, Corporate Loan | Кредиты, кредитная система |
| Payment Order | Платежи, Core |
| Product Directory, Branch Location Management | Справочные данные, MDM |

### Найти пересечения между системами FinUnion и RetailBank

В каждой области у FinUnion и RetailBank свои системы, их и нужно объединять.

| Область BIAN | FinUnion | RetailBank |
|---|---|---|
| Party Data Management | FU CRM | RB CRM |
| Customer Agreement | FU CRM, FU Core | RB CRM, RB Core |
| Current Account | FU Core | RB Core |
| Issued Device Administration, Card Transaction Switch | FU Cards | RB Cards |
| Consumer Loan, Corporate Loan | FU Loans | RB Loans |
| Payment Order | FU Core | RB Core |
| Product Directory | FU Core, FU Cards, FU Loans | RB Core, RB Cards, RB Loans |
| Branch Location Management | FU CRM, FU Core | RB CRM, RB Core |

### Подготовить целевые домены данных и data-продукты

Области BIAN задают границы целевых доменов данных, а данные домена оформляются как data-продукт с владельцем: Party Data Management — профиль клиента, Consumer Loan и Corporate Loan — кредитный портфель, Current Account и Payment Order — операции клиентов, Card Transaction Switch и Issued Device Administration — карточные операции.
