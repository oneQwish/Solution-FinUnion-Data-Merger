# Проблемные зависимости и риски на уровне данных

| Проблема | Последствие |
|---|---|
| Разные идентификаторы клиента в FU CRM и RB CRM | Невозможно построить единый профиль; клиент, обслуживающийся в обоих банках, считается в отчётности дважды |
| Единая отчётность по клиентам зависит от сопоставления в MDM | Клиент, которого MDM не сопоставил или отправил на ручной разбор, попадает в DWH без глобального ID и искажает отчётность по клиентам |
| Справочники продуктов, тарифов и отделений RB не сопоставлены с FU | Операции и договоры RB попадают в отчётности не в те продукты и регионы |
| Разные правила кредитных продуктов | Просрочка по портфелю RB, пересчитанная по правилам FU, расходится с отчётностью, которую RB сдаёт регулятору по своим правилам: по одному портфелю существуют две цифры |
| CDC зависит от структуры баз систем RB | Изменение структуры таблиц в системе RB ломает поток в MDM или DWH без предупреждения |
| Клиент RB разделён между двумя Core: новые счета в FU Core, старые в RB Core | Полная картина по клиенту есть только в DWH; операционные системы видят его частично |
| Отзыв согласия в CRM распространяется через MDM с задержкой | В течение задержки другие системы обрабатывают ПДн клиента без действующего согласия |
| Карточная операция есть в Cards (авторизация) и в Core (проводка) | Без связи между ними нельзя сверить карточные операции с учётом |
