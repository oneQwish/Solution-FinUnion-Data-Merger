# Правила владения данными

Data Steward для всех сущностей — Data Office: по структуре компании он отвечает за качество данных, каталог данных и правила владения. Владелец данных по счетам, договорам, платежам, транзакциям и кредитам — бизнес-направление по типу клиента: Розничный бизнес для физлиц, Малый и средний бизнес для юрлиц и ИП. Владелец данных по картам — Розничный бизнес: по структуре компании карты относятся к нему.

| Сущность | Data Owner | Data Steward | Producer | Consumer | Правила изменения | Правила качества |
|---|---|---|---|---|---|---|
| Клиент | Data Office | Data Office | FU CRM, RB CRM | Core, Loans, DWH, BI, контактный центр, риск-менеджмент | Записи создают и меняют CRM. ФИО, документ, дата рождения и ИНН в золотой записи меняет только MDM по правилам сопоставления; телефон и email — мастер CRM, в которой их изменил клиент. Контакт меняется по заявлению клиента (код из SMS или документ в отделении), поэтому MDM принимает последнее по времени заявление. Две разные правки одного контакта из разных CRM в коротком окне не применяются автоматически и уходят стюарду. Спорные склейки разбирает стюард вручную | Обязательны ФИО или наименование, дата рождения, документ; проверка ИНН по контрольной сумме; телефон в едином формате; адрес по ФИАС/ГАР; поиск дублей при создании записи |
| Согласие на обработку ПДн | Data Office | Data Office | FU CRM, RB CRM | MDM, DWH, Розничный бизнес, МСБ | Создаётся и отзывается только в CRM по действию клиента; отзыв сразу передаётся в MDM | Обязательны цель обработки, дата получения, ссылка на документ; отозванное согласие отражается во всех системах |
| Договор | Розничный бизнес / МСБ | Data Office | CRM, Core | Cards, Loans, DWH, Финансовый департамент | Ведётся в Core; изменение условий — через допсоглашение | Ровно один основной участник; ссылки на продукт и тариф обязательны; статус совпадает с Core; номер уникален в паре с банком-стороной |
| Счёт | Розничный бизнес / МСБ | Data Office | Core | Cards, Loans, DWH, BI, Финансовый департамент | Только Core | Ссылка на договор обязательна; номер из 20 знаков с верным контрольным ключом; остаток в DWH сверяется с Core |
| Транзакция | Розничный бизнес / МСБ | Data Office | Core, Cards | DWH, Lakehouse, риск-менеджмент, Финансовый департамент | Не изменяется; ошибка исправляется сторнирующей операцией | Ссылка на счёт обязательна; сумма и валюта заполнены; итоги по счёту сверяются с Core; карточная операция связана с проводкой |
| Платёж | Розничный бизнес / МСБ | Data Office | Каналы обслуживания, Core | Core, риск-менеджмент, DWH | Ведётся в Core; после исполнения не изменяется | Реквизиты получателя (ИНН, БИК, счёт) в установленном формате; инициатор указан; исполненный платёж связан с транзакциями |
| Карта | Розничный бизнес | Data Office | Cards | Core, DWH, контактный центр, риск-менеджмент | Только Cards | Полный номер карты вне Cards не хранится; статус из единого справочника; при перевыпуске указана предыдущая карта |
| Кредит | Розничный бизнес / МСБ | Data Office | CRM (заявка), Loans | Риск-менеджмент, Финансовый департамент, DWH | Только Loans | Связь с договором и счетами кредита обязательна; просрочка рассчитывается по правилам FU; задолженность сверяется с Core |
| Обращение | Контактный центр | Data Office | FU CRM, RB CRM | Розничный бизнес, МСБ | Ведётся в CRM оператором контактного центра | Клиент обязателен; тип и тема из единого классификатора; срок ответа заполнен |
| Продукт | Розничный бизнес / МСБ — каждый для своей линейки | Data Office | MDM | Core, Cards, Loans, CRM, DWH | Только в MDM по решению владельца линейки; новые продукты в системах RetailBank не заводятся | Уникальный код; для продуктов RB указан соответствующий продукт FU; статус продаж заполнен |
| Тариф | Розничный бизнес / МСБ — каждый для своей линейки | Data Office | MDM | Core, Cards, Loans, DWH | В MDM по решению владельца линейки; по старым продуктам RetailBank изменение до вывода систем повторяется в системе RetailBank и сверяется с MDM | Привязка к продукту обязательна; периоды действия версий не пересекаются |
| Отделение | Data Office | Data Office | MDM | CRM, Core, DWH, BI | В MDM; изменение отделения RetailBank до вывода систем повторяется в RB CRM и RB Core и сверяется с MDM | Уникальный код; регион и адрес заполнены; закрытое отделение не используется в новых записях |
| Сегмент клиента | Розничный бизнес / МСБ — каждый для своего типа клиентов | Data Office | MDM | CRM, Тариф, DWH, BI | Только в MDM по решению владельца | Уникальный код; критерии отнесения описаны; клиент относится к одному текущему сегменту |

## Карточки качества критичных данных

| Что определить | Клиент | Счета и остатки для отчётности |
|---|---|---|
| Мастер-система | MDM — идентифицирующие атрибуты, CRM — контакты | Core |
| Два критичных измерения | Уникальность: дубль в мастер-данных размножается по всем системам-потребителям. Полнота ключей сопоставления (документ, дата рождения): без них сопоставление не работает | Консистентность с Core: отчётность должна сходиться с учётом. Своевременность: отчётность строится по закрытому дню |
| Порог | Не больше 1% клиентов без глобального ID; при 3% и выше витрины по клиентам не публикуются и волна cutover не начинается | Расхождение остатков с Core — 0 копеек; данные за день загружены до 06:00 |
| Место проверки | Формат — на вводе в FU CRM; для RetailBank — на входе в MDM, так как RB CRM не дорабатывается. Уникальность — в MDM | Граница загрузки в слой core DWH |
| Стратегия для дефектных записей | Карантин: неверная склейка клиентов хуже отсрочки | Отклонить всю загрузку: частичные данные для регулятора хуже их отсутствия |
| Кто разбирает | Стюард Data Office по клиентским данным, назначается на этапе 1 плана миграции | Ответственный за отчётность в Финансовом департаменте |
