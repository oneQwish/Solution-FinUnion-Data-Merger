# Доменные data-продукты

Data-продукты выделены по областям BIAN из задания 1. У каждого продукта один владелец. Customer 360 и «Карточные операции» привязаны к источнику: ими владеет тот, кто владеет исходными данными по заданию 2. «Кредитный портфель» и «Операции клиентов» привязаны к потребителю: их владелец задаёт правила расчёта — методику просрочки или сверку с учётом. Исходные данные этих продуктов остаются за Розничным бизнесом и МСБ, которые поставляют их по контракту.

| Data product | Домен | Основные данные | Владелец | Потребители | Назначение | Интерфейс | Обновление и качество |
|---|---|---|---|---|---|---|---|
| Customer 360 | Party Data Management | Клиент по глобальному ID, сегмент, статусы согласий, продукты обоих банков; контакты — только через MDM | Data Office | CRM, BI, Розничный бизнес, МСБ, риск-менеджмент | Единый профиль клиента обоих банков | Для CRM и каналов — MDM; для BI и аналитики — витрина DWH без ПДн | Ежедневно; не больше 1% клиентов без глобального ID (карточка качества клиента) |
| Кредитный портфель | Consumer Loan, Corporate Loan | Кредиты, задолженность и просрочка по правилам FinUnion, заёмщики по глобальному ID | Риск-менеджмент | Финансовый департамент, BI | Портфель обоих банков по единым правилам для оценки риска и отчётности | Витрина DWH | Ежедневно по закрытому дню; задолженность сверена с Core |
| Операции клиентов | Current Account, Payment Order | Счета, транзакции, платежи обоих банков | Финансовый департамент | BI, антифрод | Обороты и операции клиентов для финансов и антифрода | Агрегаты — витрина DWH; детальные операции — Gold-слой Lakehouse | Ежедневно; итоги и остатки сверены с Core (карточка качества счетов) |
| Карточные операции | Card Transaction Switch, Issued Device Administration | Карты, история карточных операций обоих банков | Розничный бизнес | Антифрод, риск-менеджмент, BI | История карточных операций для антифрода и риск-моделей | Gold-слой Lakehouse, запросы через Trino | События из Kafka с задержкой до часа; без дублей, карточная операция связана с проводкой |

У каждого продукта есть контракт данных: схема, обязательные поля, правила качества, периодичность, версия и порядок изменения. Контракт хранится в Git и проверяется в CI при изменении пайплайна, а сам продукт зарегистрирован в DataHub с владельцем и lineage.

CRM и каналы обслуживания получают профиль клиента из MDM в операционном контуре; Customer 360 в DWH и Lakehouse нужен для BI, аналитики и риск-менеджмента.

Федеративное управление:

- Централизованно, Data Office: глобальный ID клиента и справочники в MDM, классификация данных и правила доступа, обязательные метаданные в DataHub, требования к качеству и карточки качества, правила изменения контрактов.
- Домены: состав продукта, его внутренняя модель и доменная бизнес-логика, приоритеты развития.
- Платформа самообслуживания, общая для доменов: Kafka и CDC, Airflow, dbt, DWH, Lakehouse, DataHub.
