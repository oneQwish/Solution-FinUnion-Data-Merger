# Cutover-план: клиентские данные

Переход клиентов RetailBank в FU CRM и на мастер MDM (этап 7 плана миграции). Выполняется после присоединения, волнами по группам клиентов: клиент переходит вместе со всеми своими договорами, счетами, картами и кредитами, чтобы оператор обслуживал его в той же CRM, где ведутся его продукты. До своей волны клиент остаётся в RB CRM, и системы RetailBank получают клиентские данные из неё, как в As-Is. Ниже — шаги одной волны; перенос финансовых данных волны идёт по плану миграции. После последней волны RB CRM выводится. Решение Go/No-Go по волне принимают Data Office — по клиентским данным и Финансовый департамент — по остаткам.

| Шаг | Содержание |
|---|---|
| Подготовка | Проверка готовности: MDM в режиме эталона не менее месяца, у каждого клиента волны есть глобальный ID: клиент, чей ручной разбор не закрыт, исключается из волны вместе со своими продуктами и переходит в следующую; по банку в целом клиентов без глобального ID не больше 1% (карточка качества клиента). Процедура отработана на обезличенных копиях на этапе 6. Резервные копии RB CRM и MDM. Операторы RetailBank обучены работе в FU CRM. Ответственные за решение Go/No-Go на месте |
| Data freeze | Для клиентов волны в RB CRM запрещено создание и изменение клиентских данных, согласий и обращений; в FU CRM их записи до переключения не меняются. На время окна запрещены изменения правил сопоставления, схем и справочников. Клиенты других волн обслуживаются без ограничений |
| Финальная выгрузка | Последние изменения клиентов волны, их согласий с документами и открытых обращений из RB CRM через CDC; снимок соответствия идентификаторов RB → глобальный ID для клиентов волны. У выгрузки есть идентификатор, временной диапазон и контрольные показатели |
| Загрузка | Финальная дельта сначала загружается в staging, ошибочные записи уходят в карантин с причиной. Затем клиенты волны — в MDM (обновление золотых записей) и в FU CRM по глобальному ID; согласия с документами и открытые обращения — в FU CRM |
| Сверка | Проверки из таблицы ниже. Остатки сверяются по каждому счёту, количество — по каждому клиенту волны; совпадения общих итогов недостаточно. Выборочная проверка карточек клиентов стюардами Data Office |
| Переключение | Каналы и операторы обслуживают клиентов волны в FU CRM; для них MDM становится единственным мастером, их записи в RB CRM переводятся в режим только чтения. После последней волны поток RB CRM → MDM отключается и RB CRM выводится |
| Фолбэк | Точка необратимости волны — первая операция по перенесённым счетам волны в FU Core. До неё откат выполняется переключением: клиенты волны и их продукты возвращаются на RB CRM и системы RetailBank, data freeze снимается, изменения, сделанные в FU CRM, переносятся в RB CRM по журналу. После неё откат требует обратного переноса операций в RB Core по журналу и выполняется только по решению Финансового департамента и Data Office. Фолбэк возможен до вывода RB CRM после последней волны |
| Мониторинг | Доля новых дублей клиентов, очередь ручного разбора в MDM, задержка потоков MDM → FU CRM и MDM → DWH, ошибки обслуживания клиентов волны в FU CRM, число отзывов согласий и их доставка во все системы, обращения к RB CRM после переключения. Стабилизация завершена, когда потоки укладываются в SLA, критичных расхождений нет и операторы работают с клиентами волны только в FU CRM |

| Проверка | Порог | Ответственный | Действие при отклонении |
|---|---|---|---|
| Клиенты волны без записи в FU CRM с глобальным ID | 0 | Стюард Data Office | Остановить переключение волны |
| Клиенты волны без глобального ID | 0 | Data Office | Исключить клиента из волны до переключения |
| Клиенты без глобального ID по банку в целом | Не больше 1% (карточка качества клиента) | Data Office | 3% и выше — No-Go, волна не начинается |
| Расхождение числа действующих согласий и открытых обращений | 0 | Стюард Data Office | Остановить переключение, разобрать записи |
| Перенесённый продукт волны без клиента в FU CRM | 0 | Инженер данных | Остановить переключение |
| Расхождение остатка по каждому счёту волны между RB Core и FU Core | 0 копеек | Финансовый департамент | No-Go, фолбэк |
| Задержка потока MDM → FU CRM | В пределах SLA потока, 5 минут | Команда эксплуатации | Проверить поток, отложить переключение |
