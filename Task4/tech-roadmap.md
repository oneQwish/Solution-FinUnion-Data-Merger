# Технологическая дорожная карта и радар

## Дорожная карта

Дорожная карта показывает, когда нужна возможность и для какого результата плана миграции.

| Горизонт | Возможности | Зачем |
|---|---|---|
| Месяцы 0–3 | Kafka, CDC и Schema Registry — с пилота на потоке RB CRM → MDM; MDM с правилами сопоставления и справочниками; DWH на PostgreSQL со слоями staging, core и витринами; Airflow и dbt; карточки качества; DataHub для мастер-данных и витрин | Промежуточный результат: единый ID клиента, матрица мастер-систем, единая управленческая отчётность (этапы 1–3) |
| Месяцы 3–6 | Открытие продуктов FinUnion клиентам RetailBank через ESB; MDM — эталон для FU CRM; DQ-контур с порогами и алертами | Новые обязательства возникают только в системах FinUnion (этап 4) |
| Месяцы 4–9 | Lakehouse: Apache Iceberg, каталог Iceberg, Trino; Spark для загрузки истории; поток событий в Bronze через Kafka Connect | История и события двух банков в Lakehouse, трассируемость (этап 5) |
| Месяцы 7–12 | Процедура cutover волны со сверкой по каждому счёту; архив RetailBank в объектном хранилище с запретом перезаписи; контракты и владельцы data-продуктов | Перенос клиентов и продуктов, вывод систем RetailBank (этапы 6–8) |

## Радар

Радар показывает, насколько банк готов использовать технологию.

| Зона | Что включено | Почему |
|---|---|---|
| Adopt | DWH на PostgreSQL, ESB FinUnion, Airflow, dbt, MDM, DataHub | DWH и ESB уже работают у FinUnion. Airflow и dbt — зрелые распространённые инструменты пакетной оркестрации и SQL-трансформаций. MDM вводится сразу в промышленный контур: спорные совпадения уходят стюардам, поэтому ошибка правил сопоставления не распространяется на потребителей автоматически. DataHub работает с метаданными и не влияет на сами данные, поэтому сбой его внедрения не ломает потоки |
| Trial | Kafka, Schema Registry, CDC (Debezium); Data Lakehouse: Apache Iceberg, каталог Iceberg, Trino; Apache Spark для разовой загрузки истории | Новы для банка: в As-Is у FinUnion только ESB, у RetailBank point-to-point. Kafka и CDC нужны уже к 3 месяцам, поэтому начинаются с пилота на одном потоке (RB CRM → MDM) в месяце 1; запасной вариант — ночная выгрузка файлом. Lakehouse вводится с пилота на истории карточных операций |
| Assess | MPP-СУБД для DWH, графовая БД для антифрода с токенизированными узлами, поисковый движок, полный Data Mesh | MPP — если объём отчётности перерастёт PostgreSQL; граф — для анализа связей по платежам после запуска целевой платформы; поисковый движок — если встроенного поиска FU CRM по обращениям обоих банков не хватит контактному центру, нечёткий поиск клиентов уже даёт MDM; Data Mesh — после того как домены объединённого банка устоятся |
| Hold | Point-to-point-интеграции, RB DWH и RB BI, витрины RetailBank как источник данных; облачные аналитические платформы | Выводятся: point-to-point заменяются Integration Layer, отчётность строится в DWH FinUnion на исходных данных по правилам FinUnion. Облако не используется: ПДн и банковская тайна размещаются в собственном контуре банка |
